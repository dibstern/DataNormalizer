# Task 7: Update DtoEmitter for JsonNameOverride — Audit Report

**Summary:** The plan has a significant logic gap around the interaction between `JsonNameOverride` and the existing `HasJsonPropertyNameAttribute` guard / `copySourceAttributes` flow, which would produce duplicate `[JsonPropertyName]` attributes (a compile error). The planned test list also has several coverage gaps for edge cases and property kind combinations.

## No issues found in:

- **State Issues**: `DtoEmitter.Emit` is a pure static method that creates a new `StringBuilder` per call. No shared mutable state, no race conditions.
- **Non-Strict Typing**: All types involved (`AnalyzedProperty`, `NamingModel`, `PropertyKind`) are well-typed with no `any` or loose generics. The new `JsonNameOverride` is `string?` which is appropriate.

---

## Summary of Critical Findings

**Must fix before implementation:**

1. **Finding #1 (Duplicate `[JsonPropertyName]` attribute)** — The most serious issue. The plan's new logic doesn't account for the `HasJsonPropertyNameAttribute` guard that prevents duplicate attributes when `copySourceAttributes=true`. This WILL produce compilation errors in generated code when both `SourceAttributes` and `JsonNameOverride` are present.

2. **Findings #4, #5, #6, #7** — Missing test coverage for Simple/Inlined property kinds, mixed DTOs, and the critical interaction between `copySourceAttributes` and `JsonNameOverride`.

3. **Finding #11** — Test descriptions are ambiguous about which `PropertyKind` to use; implementer could misunderstand the test setup.

**Needs user decision:**

4. **Finding #8** — Empty string `JsonNameOverride` behavior is unspecified.
