# Cross-Task Architectural Audit Report

**Plan:** 2026-03-25-json-contract-implementation.md (15 tasks)
**Audit date:** 2026-03-25
**Scope:** Cross-task dependencies, compilation order, shared infrastructure design

**Summary:** The cross-task design is largely sound, but has several concrete issues that will cause compilation failures or runtime bugs if not addressed before implementation. The most critical are: (1) `TypeGraphNode` is a `sealed class`, not a `record`, so the `with` expression in Task 5 won't compile; (2) the cross-type chaining rewrite in Task 4 fundamentally conflicts with the existing `GetUltimateReceiverName` mechanism; (3) the `NeedsList` computation has a logic bug in its LINQ expression; (4) the DN1002 diagnostic is referenced in Task 3 but the `GeneratorDiagnosticInfo` type it uses doesn't have a `DuplicateCollectionType` factory method and the existing type has only 2 fields (Id, TypeName).

## Audit Focus Summary

### 1. Dependency chain completeness
**Incomplete.** Finding #5 (TypeGraphAnalyzer signature change breaks compilation between Task 5 and Task 10), Finding #6 (DN1002 depends on Task 14 infrastructure), Finding #15 (Task 10 diagram missing dependencies on 7/8/9).

### 2. Backward-compatible overload strategy
**Partially correct.** Task 6's ContainerEmitter overload strategy is sound. But Task 5's TypeGraphAnalyzer signature change has NO backward-compatible overload, breaking compilation. Finding #5.

### 3. FqnHelper solves key format coupling
**Mostly, but extraction is incomplete.** `FqnHelper.NormalizeFqn` is extracted, but the analyzer has its own `GetFullyQualifiedName` with duplicated `global::` stripping. Finding #8.

### 4. Test helper defaults
**Correct.** `needsList: true` default is backward-compatible. Finding #13 (Accept).

### 5. Circular dependencies
**None found.** Finding #18 (Accept).

### 6. Task 14's DN1002 diagnostic
**Dependency issue confirmed.** DN1002 is used in Task 3 but defined in Task 14. Finding #6.
