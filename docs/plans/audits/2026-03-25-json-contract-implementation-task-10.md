# Task 10: Wire JsonContractModel through NormalizeGenerator -- Audit Report

**Summary:** Task 10 has a critical compile-time breaking change (ContainerEmitter.Emit signature change) that will break all existing tests, but the task contains NO new tests and relies entirely on prior tasks having been implemented. More importantly, the task's description of what needs to change in NormalizeGenerator.cs is incomplete: it only mentions the ContainerEmitter call but ignores that NormalizerEmitter and DenormalizerEmitter also need access to `rootNode.NeedsList`/`rootNode.IsRootType`, and the plan handwaves this by claiming they "flow through the existing `allNodes` parameter" -- which is only true if Task 5 has already modified `TypeGraphNode` to include those fields AND Task 8/9 have already modified the emitters to consume them.

**Key Risk Assessment:**

The biggest risk with Task 10 is that it is a **pure wiring task with no tests of its own** that depends on **5 prior tasks** being fully implemented. The "Run all generator tests" step is misleading because:

1. After Task 6 changes ContainerEmitter.Emit's signature, ALL existing ContainerEmitter tests will need updating (Task 11).
2. After Tasks 8/9 change NormalizerEmitter/DenormalizerEmitter behavior, existing tests for those will also break (Task 11).
3. There is no E2E test that exercises the full JsonContract pipeline until Task 12.

This means Task 10 exists in a window where existing tests may be broken (awaiting Task 11) and new behavior has no test coverage (awaiting Task 12). The task should acknowledge this explicitly.
