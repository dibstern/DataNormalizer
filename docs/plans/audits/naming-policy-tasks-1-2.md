# Tasks 1 & 2: NamingModel/JsonContractModel + Runtime Configuration Classes -- Audit Report

**Summary:** Tasks 1 and 2 are structurally sound additive changes. The main concern is a factual error in Task 1's acceptance criteria claiming new defaults "match old behavior" (they don't -- they match the NEW desired behavior), and a potential ambiguity between the old `JsonNamingPolicy` field and the new `NamingModel.EmitJsonPropertyNames`. There are also findings about `IEquatable` justification and the `JsonContractModel.GetHashCode` implementation being weak.

## Key Observations

1. **Default value mismatch is not a bug** -- The new defaults (`"Dto"` suffix, `EmitJsonPropertyNames = true`) represent the desired NEW behavior, and they won't affect anything until emitters are wired in Tasks 6-9. The plan text is simply misleading.

2. **JsonContractModel hash weakness is real but minor** -- In practice, the dictionary will likely have few entries, so hash collisions are unlikely to cause performance issues. But for a source generator where pipeline caching correctness matters, a stronger hash is worth the 3 extra lines of code.

3. **Attribute consistency** -- The missing `Inherited = false` on `NormalizeJsonNameAttribute` is a minor style inconsistency but worth fixing during implementation to match the project's conventions.
