# Task 12: Add integration tests for full search-response use case — Audit Report

**Summary:** Task 12 is well-structured and covers the main JSON contract features, but has several significant gaps: (1) it cannot compile as written because Tasks 1-11 introduce breaking changes to the container shape (root property replaces list access) that will require Task 12's test assertions to account for both `Result` and list properties in specific ways; (2) the `SearchNormalizationConfig` puts `ForType<SearchHop>` at the builder level but `UseJsonContract` inside the graph lambda, creating a parser scoping mismatch for `PropertyJsonNameOverrides`; (3) several test coverage gaps could allow real bugs to ship uncaught.

## Summary of Critical Findings

1. **Finding #1 (Amend Plan):** The `ForType<SearchHop>` at builder level combined with `UseJsonContract` at graph level creates a cross-cutting concern. The plan should ensure the parser correctly scopes `PropertyJsonNameOverrides` to the right graph when `ForType` is at builder level.

2. **Finding #2 (Amend Plan):** The most important missing test is the full JSON roundtrip (serialize → deserialize → denormalize). Custom JSON names on DTO properties must survive deserialization — this is the whole point of the feature but isn't explicitly tested.

3. **Finding #10 (Ask User):** Step 6's `SearchPlace`-as-root test needs a design decision about whether to create a second config class and duplicate generated DTOs.

4. **Finding #15 (Amend Plan):** The TypeGraphAnalyzer signature mismatch means Task 12's tests can't pass unless Tasks 5 and 10 correctly thread the new model properties through the existing API. The plan should call this out as an explicit dependency.
